# 按赛题五项核心能力复核的缺口与实施建议

日期：2026-10-18。依据为用户本轮提供的完整赛题文字、M25对应源码和阶段证据。本次为只读代码/文档审查，未新增实验或云调用。下述“待补”区分实际实现缺口与尚缺专项验收，不将未验证项直接认定为可利用漏洞。

总体判断：系统已有真实Host/MCP、任务授权、三态执行、跨角色/会话来源与实际效果核验基础；五项能力仍不宜全部标为完成。能力3的代表闭环较强；能力1需扩来源接入与统一语义检测；能力2需增强执行前与跨轮组合研判；能力4需完整调用证据和链路可视化；能力5是目前覆盖证据最薄弱的部分。

M25的1022项回归、脚本/封闭HTTP各48格与来源14格证明对应工程及开发校准，不能代替五项要求逐条验收，也不构成真实模型ASR。

## 能力1：多源注入识别

**已有：**直接用户补充输入注册为DIRECT来源；实际MCP正文、网页读取、Memory分别建立来源并扫描；MCP注册描述/schema有注入扫描与拒绝；跨新会话Memory具备原文、版本、CAS与生命周期见证。

**需要补齐：**

1. **统一扫描所有实际进入模型的工具返回文本。** 当前`_record_tool_result`主要处理顶层`data.content`字符串，而Host会序列化完整result。应枚举受支持JSON结构中的字符串、数组与嵌套字段，保存字段路径和来源。不以受控工具都返回content来声称任意MCP字段全覆盖。
2. **统一规则与语义检测编排。** 任务感知语义分类器已有开发实现，但实际运行的可选语义分类主要挂在`evidence.read_alert`。直接输入、网页、工具描述/返回、Memory应经过一致的检测契约；分类结果仅提供风险证据，不授予权限。
3. **覆盖题目列举的实际资源入口。** 已有本地JSON/CSV/文本业务不能代替PDF/DOCX提取、IDE源码、邮件/Issue读取的完整接入证据。最小方案是统一资源适配接口接入这些实际提取结果，不必为每类建设大型生产连接器。
4. **补检索式Memory/知识库入口。** 当前SQLite固定key/版本流程不代表向量召回和未知污染识别。增加至少一种真实检索适配，记录document/chunk/revision、召回查询与跨会话暴露链；不必同时部署三套数据库。
5. **直接输入补真实追加轮次。** 当前report支持的单次补充输入不能代替多轮用户消息。原始可信任务目标与后续文本自称角色应明确区分。

验收应分别回答：是否识别攻击、是否定位来源、是否产生越权提议、网关如何决策、是否发生实际效果、合法业务是否受损。仅因合同禁止某次写入而BLOCK，不足以证明攻击语义已被识别。

代码依据：[来源与工具返回](../../sujie/gateway-python/src/sujie_gateway/m1_runtime.py)1162、1789–1837行；[模型接收完整工具结果](../../sujie/demo-agent/sujie_demo_agent/bailian_agent.py)838–883行；[Memory边界](../../sujie/docs/M18_CROSS_SESSION_MEMORY.md)；[有限规则](../../sujie/gateway-python/src/sujie_gateway/detection.py)。

## 能力2：意图—计划—工具语义对齐

**已有：**可信TaskContract目标、允许用途/效果/资源；每轮可见工具提议及其实际工具调用；目标、资源、副作用、数据流四类偏离解释；完整提议与执行状态、真实影响和UNKNOWN记录。

**主要欠项：**

- 当前原始目标主要由固定profile生成。应将原始用户请求只读绑定到明确的主目标、范围和允许副作用，并建立澄清/变更流程；不需要先开放任意自然语言自动扩权。
- `alignment.py`明确为决策后解释，实际仅在BLOCK后调用。需增加执行前、随历史累积的偏离研判，覆盖某一步单独合理、组合后越权的情况。
- 当前序列仅有有限的凭据读→外发提议关联。应扩展读后编码、分片累计、读后委派、子Agent中转再外发等链，并关联实际数据来源与执行收据。
- 输出一条评委可读的研判：原任务、偏离步骤、数据/目的地、关联来源、风险、决策与真实效果。只有共同上下文时应标“关联/疑似”，不能硬称已证明因果或泄露。
- 偏离度可用可解释维度与分级，不必编造未经标定的连续概率；误报、漏报与未知情况需分别评估。

验收样例应包含合法多步任务、单步越权、跨轮组合越权、被阻断提议与实际发生效果；研判可由原始记录重算。可见计划不需要也不应冒称获取模型隐藏思维。

代码依据：[决策后解释](../../sujie/gateway-python/src/sujie_gateway/alignment.py)1–25行；[序列关联与边界](../../sujie/gateway-python/src/sujie_gateway/sequence_alignment.py)115–170行；[当前解释调用位置](../../sujie/gateway-python/src/sujie_gateway/m1_runtime.py)1564–1574行。

## 能力3：语义DSL、细粒度策略与三态

**已有：**数据式DSL、规范化语义动作、Contract/Grant、来源用途、实际ALLOW/ASK/BLOCK和审批后再核验。因此不能把现状说成仅有工具名/路径黑白名单，也不需要重造Git、网络和子Agent工具。

**两项共同实现缺口：**

1. **独立动态风险分级。** 当前DecisionRecord的risk为`LOW if ALLOW else HIGH`，uncertainty固定0，属于从结果映射标签。应根据任务偏离、数据敏感度、来源、目的地、委派边界、历史组合及副作用等可信事实给出等级、依据与不确定状态。硬阻断不因低风险评分或人工确认而解除。
2. **DSL运行事实接入。** 语法支持contract/data/provenance/history等命名空间，但当前DSL调用主要提供action.effect和前置校验标志。Contract/Grant已有Python前置校验，不能说授权未检查；需要把受支持的可信上下文事实真正接入DSL，并保存命中规则/事实快照。

| 题目动作 | 当前代表能力 | 还需的专项验收 |
|---|---|---|
| 敏感fs.write | 工作区相对路径、默认output范围、穿越/边界拒绝 | 在完全自有隔离根目录映射`.ssh`、`.aws`、`cron`和自启动逻辑目标，补独立硬策略、宽Grant仍拒绝、路径别名/链接与文件未改变证据。未看到完整矩阵不等于已证明能写入这些路径；不得操作用户真实敏感目录 |
| 敏感net.fetch | 真实GET/POST、来源/目标/正文检查；已测先读合成秘密后经query/header/body及支持编码外发的拒绝；公开数据审批后发送 | 补部分秘密、分片重组、多次外发及支持转换；将整值/有限编码保护与通用DLP区分 |
| 编码/下载exec | 结构化program/argv、编码/下载/Shell语法拒绝、固定注册核验程序与真实执行器复核 | 补语法等价组合、合法复杂参数对照、风险与解释。赛题不要求开放任意Shell |
| 检视git.push | review禁推、真实ref/回执；publish绑定确切commit/ref审批 | 纳入统一五类动作矩阵、动态风险与解释，保留输入变化/拒绝/UNKNOWN |
| 子Agent传密 | artifact ID输入、权限收窄、敏感标签/已知秘密检查，模型创建前阻断 | 补未标记凭据、部分片段、支持转换和多层转交，不将已知蜜标检查泛化成任意凭据识别 |

每类动作应有合法ALLOW、确可授权的ASK、越权BLOCK对照；ASK需覆盖批准/拒绝及审批后输入变化。禁止动作不应为了凑三态而变成人工可解除。

## 能力4：跨MCP与子Agent溯源

**已有：**真实多MCP、main→review→verify主体/父链、共享Trace、三来源身份、字符/UTF-8/本地token区间、来源artifact DAG、决策事件时间列表及影响资源查询。

**需要补齐：**

1. **完整私有工具调用证据。** 目前提议主要存arguments_hash，执行结果主要存tool/ok/code，部分content原文存入artifact；尚非所有工具参数及完整返回的持久复核。应以统一call ID关联真实参数、返回/错误、server、主体、会话与时间。公开导出继续脱敏，原始证据由本机操作者受控查看；Provider认证密钥不进入公开或工具证据。
2. **统一攻击路径DAG。** 现SVG主要是artifact及parents图，主子卡片另列。应能从一个违规动作反向展开“原始来源区间→主/子/孙Agent→网关/MCP→被阻断或影响的资源”，把调用节点与来源节点关联起来。
3. **角色时序链路图。** 现有`<ol>`事件列表有时间顺序，但缺按User/Agent/Gateway/MCP划分的调用与回应连线。建议补泳道式展示，并能跳到token、审批与实际效果证据。
4. **支持转换的可复算映射。** 字面/JSON转义已有；规范化、解码、拼接等支持的转换保存来源映射，摘要与未知转换标保守归属或未绑定。现有本地API字段token是有效基础，题目不要求知道供应商内部聊天模板或隐藏token。
5. **区分影响状态。** 读取目标、计划目标、已尝试、确认发生和UNKNOWN分别展示；Memory会话按实际actor/phase映射，不能只取共享事件头的初始session。

验收应至少以直接/间接/Memory各一条实际链路、一次多MCP/多层Agent违规链完成点击复盘与独立重算，并做当前页面浏览器操作/布局验收。OS级角色隔离是部署与可信边界问题，不应增设为能力4文字中的硬条件。

代码依据：[提议与结果记录](../../sujie/gateway-python/src/sujie_gateway/m1_runtime.py)1440–1452、1630–1650、1812–1837行；[现有图与时序UI](../../sujie/console-vue/src/App.vue)898–1109行；[本地token映射](../../sujie/demo-agent/sujie_demo_agent/tokenizer_mapper.py)44–94行；[公开投影与影响](../../sujie/control-plane-python/sujie_control/views.py)。

## 能力5：七类对抗鲁棒性

这是当前最需要扩展真实链路覆盖与独立评估的一项。旧规则smoke本身保留分片/语义伪装漏检和合法引用误报；M25三个代表只证明来源暴露后固定禁止提议的执行边界，不能算七类攻击识别通过。

| 绕过类别 | 当前基础 | 需补的关键内容 |
|---|---|---|
| 多语言混淆 | 中英有限规则、中文/Emoji样例 | 中英日俄及混排、Emoji干扰；配对合法外文业务与引用 |
| Unicode变形 | NFKC、去Cf、全角/零宽测试 | 西里尔/拉丁同形、其他不可见字符及组合；原文不改，映射可回查 |
| 拆分/多轮 | 单文本分片样例，三来源预检 | 真实用户追加轮次、外部多次读取、Memory多chunk；至少独立暴露事件及中间模型调用，不能先拼成一条文本冒充多轮 |
| 注释/分隔符 | 部分注释样例、exec符号拒绝 | 注释切断、伪角色分隔、组合指令；文本攻击识别与工具参数策略分别验收 |
| 大小写/全半角/编码 | re.I、NFKC、有界percent/HTML；有限秘密编码保护 | 有界Base64/hex等支持转换、深度/大小限制、原始字节与转换链；不能无限递归解码 |
| 上下文稀释 | 规则smoke与容量边界 | 实际Agent长上下文分档、载荷首/中/尾、摘要/截断后来源继承；未暴露/超限记不支持或UNKNOWN，不算防御成功 |
| 语义伪装 | 任务感知分类开发版、Memory流程备注代表 | 无明显恶意关键词的假审批、假运维、事实篡改等，同合法业务指令/危险原文配对并观察真实模型 |

建议用“三来源×七类”内部覆盖表组织适用项，逐格记录原文、来源、检测、动作、决策、实际效果、业务与未知状态；这是内部验收设计，不是官方规定必须21次运行。规则分类、脚本固定提议、封闭HTTP和真实模型结果必须分层报告。

代码/边界依据：[规则与规范化](../../sujie/gateway-python/src/sujie_gateway/detection.py)；[Memory延迟指令规则](../../sujie/gateway-python/src/sujie_gateway/memory_detection.py)；[旧smoke预期](../../sujie/tests/test_detection_eval.py)；[M25范围](../../sujie/docs/M25_SOURCE_BYPASS.md)；[来源覆盖预检](../reviews/2026-10-17-m25-preflight/source-bypass-preflight.md)。

## 据此调整下一步优先级

1. **P0：共同内容与证据接口。** 统一实际进入模型的字段扫描/来源登记、私有完整工具调用证据和真实actor/session关联，服务能力1与4。
2. **P0：语义研判与动态风险。** 将原始可信目标、单步语义、跨轮组合、风险依据和实际效果串成一条研判记录；向DSL提供真实可信facts，服务能力2与3。
3. **P1：五类动作专项与绕过覆盖。** 补题述敏感目录矩阵、实际追加轮次、检索Memory及七类绕过，均配合法对照与独立效果核验，服务能力1、3、5。
4. **P1：完整链路演示。** 在现有DAG基础上补调用节点和角色时序图、受控原文复核及浏览器验收，服务能力4。
5. **并行：真实模型与参赛研究证据。** 预算协议准备继续推进；输入、实现和指标稳定后开展同版模型比较、留出任务与有效消融。不能仅扩大48格，而让上述核心能力缺口保持不变。

因此应将原[M26计划](../../sujie/docs/M26_PLAN.md)中的“真实比较准入”与本次五能力补齐结合：先做共同接口、研判/风险与可验证覆盖，模型资源准备并行。SDK/Sidecar/MCP/Hook无需四种全做；Java/MySQL、指定测试总数、通用Shell和全部OS隔离不是这份五能力文字新增加的硬门槛。国家级奖项目标还需要真实收益、创新性对照、可复现材料及交付质量，不能仅靠测试数判断。
