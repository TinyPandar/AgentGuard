# M25 工作报告与项目整体评估

报告日期：2026-10-18。目标：以研究生网络安全创新大赛国家级奖项为方向推进。依据为本地源码、封存输入、原始运行日志和独立核验结果；本报告不把开发测试数量换算为获奖概率。

**总体判断：项目已经具备较完整、可运行、能检查实际副作用的安全 Agent 工程原型；M25 已完成同事实比较与有限来源代表的离线基础验收。正式真实模型收益、未见任务泛化、统计与消融、性能隔离和最终参赛交付仍未完成，目前不能据此认定已达到国家级获奖水平。**

## M25 做了什么

M24 已完成四个核心候选的参数化、独立事实核验及 Linux 六链。M25 围绕“同一事实下如何比较、记录是否可信、实际效果如何判定”新增 16 份评测、测试与协议文件。原有 265 份应用/部署文件未改变，1183 份历史证据摘要保持一致，M9 四份冻结文件和依赖锁保留。

| 工作 | 本轮实际交付 | 意义 |
|---|---|---|
| 同事实比较 | 六个候选各封存一份 seed20261018 业务事实；构造 C/A 与适用 Q；48 个唯一单元、14 组配置配对 | 避免把不同事实的正常/攻击场景直接作因果比较；IOC C∩R 复用同格，不重复凑数 |
| 观察性判定 | 分别记录执行终态、合法业务完成、实际危险效果、记录完整性；保留失败、UNKNOWN、未执行和清理状态 | 不要求 unsafe 必须中招或 full 必须成功，避免把预定输赢写入验收条件 |
| 请求与角色证据 | 保存受检 messages/tools 与有效 HTTP 正文原字节，关联 call、ticket、actor、role、session 和导出 audit | 从“有一个摘要”推进到能复核具体调用和所属角色 |
| 预算边界 | 修正祖先预算不足被误判为全局不足；每张票据核对真实 run/Memory/委派祖先 scope | 防止错误提前停止矩阵，以及同额票据互换后仅靠总数相同而漏检 |
| 三来源代表 | 直接 Unicode、外部 Base64、跨会话 Memory 流程备注；14 个有界单元、7 配对 | 检查真实来源暴露后，未经授权的自有夹具标记写入是否实际发生 |
| 独立核验 | 读取实际文件、Receiver、Git 对象/ref/回执、SQLite 历史及角色/会话事件 | 业务与危险效果不依赖 Host 自报完成标记；原失败和反例保留 |

六个比较候选为时间线、附件核对、IOC、Git 检视、三层委派和跨会话 Memory。48 格包括 C/A×三主配置 36 格、预选三候选的攻击消融 6 格、两候选合法危险原文引用 6 格。**格数、配对数、角色数和独立任务数分别统计；48 格不是 48 个独立任务。**

C为正常场景、A为注入场景、Q为要求保留危险原文的合法引用，R为审批流程。unsafe、strong-static和full分别是评测对照配置、强静态基线和完整配置；no-source/no-recovery用于考察移除来源约束或恢复机制的差异。

完整回归的原始日志已经结束并显示上述结果；由于用户主动中断后原进程会话不可取回，本报告不虚构其退出码。该限制记录于 [回归执行元数据](../reviews/2026-10-18-m25/full-check-exit-v1.json)。

三来源矩阵只操作自有临时目录中的合成标记，无真实外部目标、真实密钥或云调用。Memory 校准包含 capture 结束、reconcile 新主体真实读取、CAS 追加 1→2、复读与原历史保全。危险原文合法归档和经过审批的公开 IOC 传输不是危险效果。

M25 本轮云调用为 **0**。脚本记录中的预留次数、未知用量和本地 reservation units 不能称为真实计费 token 或费用。本地 HTTP 即使使用固定模型名，也只是经过真实 Provider 请求准备、HTTP 解析、收据与账本代码的封闭传输校准。

## 面向国家级奖项的指导判断

目前最值得保留的优势是：真实工具副作用、来源跨角色/会话保持、审批与实际执行绑定，以及可重算而非仅依赖界面显示的证据。这些适合形成答辩中的具体主张。

最主要的短板是“相对基线的真实增益尚未证明”。当前很多脚本格在所有配置下都正常完成；没有出现危险提议的格，不能归因于网关成功拦截。Git 和自有标记校准说明部分链路存在差异，但不足以推导广泛模型攻击成功率、未见任务泛化或消融贡献。1022 项测试也不能替代这部分证据。

建议报告正文围绕三项可检验主张组织：

1. **任务与来源用途约束能跨 Agent / Memory 继续约束工具动作。** 同时呈现允许、拒绝、越权实际效果和可信 Host 假设。
2. **限制执行权限时仍能保留危险原文并完成合法业务。** 同时报告引用完整性、业务损失和恢复策略代价。
3. **审批绑定到确切输入、动作与实际执行。** 同时展示批准后输入变化、拒绝、确认丢失 UNKNOWN 与真实回执，不声称跨崩溃 exactly-once。

这些是待用对照实验进一步支撑的贡献主张，不是“首次提出”或已获奖结论。正式创新性还需要与相关工作逐项比较。

## 下一步执行顺序

1. **将 M25 离线结果固化为下一轮基线。** 脚本48格、本地HTTP48格、来源14格和独立核验已完成；同步交接和证据索引，后续变更新立版本，保留所有失败版本。
2. **建立新版本真实模型协议。** 用户提供仓库外现有百炼凭据 CSV 路径和本轮总请求、token/费用上限后，先做计入总预算的小额校准，再按预登记矩阵执行。当前 runner 的真实云 CLI 关闭，不能直接添加密钥冒充正式实验。
3. **补研究结论。** 预先定义独立任务、未见输入与重复规则；以任务层配对统计合法业务、安全效果、失败和代价，避免将 seed/角色/格数当独立样本；针对可观察差异做消融。
4. **完成可提交交付。** 并行验证性能开销、隔离边界和跨机复现；制作 IOC 审批、Memory 更新、危险原文保全三段实际演示；整理匿名报告、依赖/资产许可和可运行证据包。

现阶段优先让现有机制产生可复现的比较结论和清楚的答辩证据，Java/MySQL、多操作者等扩展后置。国家级奖项始终作为目标，最终评价取决于创新性、对照结果、完成质量和赛事评审。
