# 溯界（Sujie）部署说明

> 对应初赛提交件「部署说明」。目标是让评审在**干净机器**上复现：确定性演示、离线核验与可选云模型任务。
> 事实依据：`sujie/docs/PROJECT_HANDOFF.md`。**未验收项在文末统一标注**，请勿把设计目标当作已验收结果。

## 1. 环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| Python | **3.12.x** | 按 `sujie/requirements.lock` 安装 |
| Node.js | **20.19+ 或 22.12+** | 仅前端控制台构建需要 |
| Git | PATH 中可执行 | 仅 `git-review` / `git-publish` 业务需要 |
| 网络 | 安装期需要 | 拉取依赖、首次分词器资产、前端安装；**无密钥模式不等于新机完全离线安装** |
| Docker | 可选 | 仅用于历史 M1 容器链路验证 |

不要拷贝他人的 `.venv` 或 `node_modules` 当作可移植环境。

## 2. 安装（macOS / Linux，仓库根目录起）

```sh
cd sujie
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pip check
.venv/bin/python dev.py prepare-tokenizer
cd console-vue && npm ci && npm run build && cd ..
```

Windows 使用 `.\.venv\Scripts\python.exe` 与 `dev.py` 的同名子命令。

`prepare-tokenizer` 只下载固定 revision 的公开 `tokenizer.json`（清单 `assets/tokenizer/qwen3-local-manifest.json`，缓存 `model-cache/`），**不下载模型权重**，运行时不自动补下载。该步骤需访问外部站点；若不可达，相关 token 映射测试会标注跳过，**不能声明 token 映射已验证**。

## 3. 无密钥启动

```sh
.venv/bin/python dev.py demo      # 确定性演示：可信授权→来源传播→三态决策→真实副作用
.venv/bin/python dev.py console   # 操作台（默认 127.0.0.1:8765）
```

打开 `http://127.0.0.1:8765`，本机查看 `.control-runtime/operator-token.txt`，把操作者凭据粘贴到页面。服务只绑定 loopback；凭据仅存于页面内存，刷新需重新登录，每次启动生成新凭据。**不要把凭据写入文档、日志或提交包。**

未配置模型时可运行确定性演示、手动固定动作与离线核验；自主云模型任务需要第 4 节的 Provider。

## 4. 云模型（可选）

当前 Provider 为阿里云百炼兼容接口，固定 `qwen-plus-2025-12-01`。凭据 CSV 经私密渠道交接、置于仓库外，仅由可信 Provider 加载；**不入页面、不入 MCP、不进入模型消息或导出**。

```sh
.venv/bin/python control-plane-python/run_console.py \
  --port 8767 \
  --credentials-file /path/to/bailian-credentials.csv \
  --model-budget-file .control-runtime/model-budget-8767.sqlite3 \
  --max-provider-requests 60 --max-reservation-units 1000000
```

预算要点：服务共享账本默认 60 请求 / 1,000,000 预留单位；任务共享预算默认 12 请求 / 200,000 预留单位（子角色共用）；预留单位**不是** token 或真实账单。本地预算不保证供应商账单上限。IOC/Git 待审时**批准不执行、提交才执行**；提交再次核对输入、工具、合同/Grant、策略、状态与来源，确认丢失标 `UNKNOWN` 并停止，不自动重发。

## 5. 无云复现与验证

以下命令不会主动调用云 Provider：

```sh
.venv/bin/python dev.py check
.venv/bin/python -m pytest tests/test_business_workflows.py tests/test_evidence_analysis.py -q
.venv/bin/python eval/verify_runtime_validation.py eval/reports/runs/four_business_m21_scripted_v3
```

`dev.py check` 含 ruff 检查、格式检查与全部 pytest。要生成新的四业务确定性校准，输出目录必须是新的（无 `--credentials-file` 时使用脚本模型）：

```sh
.venv/bin/python eval/run_business_validation.py \
  --protocol-file eval/protocols/four_business_workflows_v2.json \
  --out-dir eval/reports/runs/<新目录>
```

## 6. 部署形态与隔离约束（历史容器拓扑）

`deploy/m1.compose.yaml` 是**历史 M1**确定性容器链路：两个 Docker internal 网络（Agent 只连 `agent-net`，Receiver 只连 `tool-net`，Gateway 连接二者），Agent 镜像不含 Gateway/MCP 源码、不挂载测试工作区、无审批 API。成功标准为 Agent 输出 `receiver_directly_unreachable=true`、`external_network_unreachable=true`、`secret_mount_absent=true`、`docker_socket_absent=true`。

```sh
sh deploy/run_m1_container_test.sh
```

该拓扑**不覆盖**当前全部模型、子 Agent 与新增工具；`deploy/compose.yaml` 是 M0 历史占位，**不作为部署或隔离证据**。

## 7. 已知限制与未验收项（务必如实告知评审）

1. **新版整体隔离与性能未验收**：当前完整 Host/工具/子 Agent 拓扑尚未在 Linux 环境验收；历史 M1 不能替代新版拓扑。
2. **Git 业务在 macOS 上不可用（环境限制）**：`sandbox/sealed_git.py` 的来源账号检查 `path_identity()` 会拒绝任何祖先含符号链接的路径（设计如此，用于拒绝路径别名）；而 macOS 的 `/var` 是 `/private/var` 的符号链接，系统临时目录（含 pytest `tmp_path`）因此命中 `GIT_ALIAS_FORBIDDEN`，导致 Git 相关用例在 macOS 全部失败。Linux/Windows CI 不受影响。**这是在 macOS 上运行测试夹具的可移植性限制，不是授权/绕过缺陷。** 规避方式：让夹具根目录先 `resolve()` 后再创建。
3. **离线安装并非完全离线**：依赖、分词器资产与前端初次安装需网络。
4. **控制面实现范围**：控制面为 Python 实现，原设计中的 Java/MySQL 控制面未落地；子 Agent 运行于同一宿主进程内，未做操作系统级隔离。
5. **无密钥 ≠ 无云**：确定性演示与离线核验不调用云模型；但“云调用为 0”只描述当次运行，不能推广为系统不含云路径。

## 8. 打包与命名

提交时按官方要求命名：`队长姓名+作品名称+资料名称`。源码与证据打包时应排除 `.venv/`、`node_modules/`、`model-cache/`、`.control-runtime/`、原始未脱敏证据与任何凭据文件。
