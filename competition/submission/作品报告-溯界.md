# 作品报告

作品名称：**溯界（Sujie）——面向大模型智能体的运行时安全网关**

提交日期：2026 年 10 月

---

## 摘要

大模型智能体已能自主规划任务、调用工具、读写文件与访问网络，MCP 成为工具调用的事实标准；能力扩张同步放大了攻击面——提示注入可经直接对话、外部网页与文档、MCP 工具描述与返回、长期记忆等渠道进入上下文，诱导智能体滥用自身合法权限，实施秘密外发、敏感写入、下载执行与代码推送等越权操作。传统 WAF、EDR、DLP 工作于报文与系统调用层，难以理解智能体“意图—计划—工具”的语义链路。

本作品“溯界”是部署在智能体宿主与 MCP/本地工具之间的运行时安全网关：以**可信任务契约**冻结授权边界，以**来源—用途信封**约束不可信内容的传播与使用，以**效果级执行闸门**对真实工具动作实施放行/确认/阻断，并生成跨 MCP、子 Agent 与记忆的可验证攻击链。系统坚持“模型提议不等于授权”——模型输出、工具描述、记忆正文与子 Agent 结果一律只能作为数据；攻击动作被阻断后，返回不含秘密的结构化安全异常，引导智能体在原授权边界内重新规划并继续完成安全研判。作品以文件、网络、进程、Git 与记忆的真实副作用作为安全判定的 Oracle，支持容器化部署（部署验收状态见第三章），可作为企业智能体平台在真实工具链上落地运行时防护的组件。

**关键词**：大模型智能体；提示注入；工具滥用；MCP；运行时安全网关；来源—用途约束；三态决策

## 第一章 作品概述

### 1.1 背景分析

2024 年以来，以 Claude Code、Cursor、Devin、通义灵码等为代表的“大模型智能体”已从对话问答系统进化为可自主规划、调用工具、读写文件、访问网络、操控浏览器与 IDE、派发子 Agent 的准代理人系统。Anthropic 主导的 Model Context Protocol（MCP）已成为行业中事实上的工具调用总线：开源社区每周新增数百个 MCP Server，企业内部广泛通过 MCP 接入 IM、工单、代码托管、堡垒机与 SOC 平台。

能力边界的拓展同步带来攻击面的扩张。当前面向智能体的主流高危攻击方式包括：

1. **直接提示注入**：用户在对话中直接植入“忽略上文、执行指定恶意指令”类内容；
2. **间接提示注入**：载荷隐藏在智能体抓取的网页、邮件、PR 描述、代码注释、Issue 评论、PDF 元数据、MCP 工具返回字段中，被作为正常上下文读入后触发；
3. **MCP 工具链供应链攻击**：恶意或植入后门的第三方 MCP Server，通过工具描述注入隐藏指令，或在返回结果中嵌入二阶攻击载荷；
4. **记忆污染**：跨会话长期记忆库、向量库、知识库被写入隐性触发指令，在下一次会话启动时自动激活；
5. **工具滥用**：攻击者诱导智能体滥用自身合法权限，如写入敏感权限文件、外发本地配置、执行远程下载脚本、推送恶意代码提交等。

OWASP 已将 Prompt Injection 列为《LLM 应用安全十大风险》的 LLM01 头号风险；2024—2026 年，GitHub Copilot、Slack AI、Microsoft 365 Copilot 与 Anthropic MCP 生态等已出现可真实利用的安全漏洞（如 CVE-2024-49035、CVE-2025-53773）。

传统防护设备无法胜任这一新对象。WAF、EDR、DLP 工作在**网络报文层与系统调用层**，只能看到字节流与进程行为，无法理解智能体“意图—计划—工具调用”的全链路语义逻辑，对上下文中的隐蔽指令、嵌套工具滥用、跨子 Agent 协同攻击、跨会话长时记忆污染几乎没有感知能力。

因此，本赛题要求构建面向大模型智能体的提示注入与工具滥用检测防御技术，具体包含五项能力：多源提示注入识别、意图—计划—工具序列对齐、语义化策略描述与三态处置、跨 MCP 与多层 Agent 的溯源防护，以及对多语言与多种绕过手法的覆盖；并要求覆盖七类绕过：多语言/Emoji、Unicode 同形与零宽字符、分片/多轮、注释与分隔符、大小写/全半角/编码、超长上下文稀释、语义伪装。

### 1.2 相关工作与边界

智能体安全已成为公开研究热点，已有工作从不同角度给出机制：把不可信数据与可信指令在体系结构上分离（CaMeL[1]）、以任务对齐约束工具调用（Task Shield[2]）、用策略语言约束智能体行为（AgentSpec[3]）、对工具调用做认证授权图（AuthGraph[4]）、将智能体置于受控执行环境（AgentVisor[5]、ContainmentBench[6]）、面向工具调用链的隔离与检测（AID-Guard[7]），以及面向 MCP 与工具链的安全基准（MCP-SafetyBench[8]、MCPTox[9]）。在工业界，提示注入被 OWASP 列为 LLM 应用首位风险[10]；MCP 规范亦明确要求宿主在调用工具前取得用户显式同意，并提示工具描述等元数据应视为不可信[11]。

本作品**不宣称**任务授权、污点传播、策略 DSL、三态审批、运行时网关或提交复核等单项机制为首创。本作品的贡献在于面向“安全研判”这一特殊场景，把可信任务契约、来源—用途传播、效果级策略、隔离分析与攻击后任务恢复组合成真实 MCP 防护闭环，并以安全与业务双 Oracle 加以工程验证。

需要明确的是，本作品**不是**：只有一个提示注入分类器的系统；依靠另一个大模型决定一切的“安全 Agent”；对 Cursor/Claude Code 的重实现；只做前端展示的普通应用；也不是对任意第三方远程 MCP Server 内部行为作出保证的通用沙箱。

### 1.3 作品定位与特色

**一句话定位**：溯界部署在智能体宿主与 MCP/本地工具之间，以可信任务契约冻结授权边界，以来源—用途信封约束不可信内容的传播与使用，以效果级执行闸门实施放行/确认/阻断，并生成跨 MCP、子 Agent、记忆的可验证攻击链。

作品争取形成三项**组合贡献**：

1. **来源—用途约束**：不可信证据可被分析、引用与受控存档，但不能经摘要、记忆、子 Agent 或工具返回升级为执行授权；
2. **攻击后的安全任务持续执行**：阻断越权副作用后不简单终止任务，而是通过结构化安全异常与证据隔离路径继续完成原始研判；
3. **效果级工程闭环**：对真实工具参数、来源依赖、任务授权与执行状态做统一判断，以真实的文件、网络、进程、Git、记忆副作用作为安全 Oracle。

**特色演示主线**：用户要求分析一份包含危险命令的告警附件并生成报告。系统允许读取并解释攻击内容；但攻击内容中“读取凭据并外发”的指令不能成为智能体指令；越权工具调用被阻断；智能体获得不含秘密的结构化安全异常后重新规划；报告仍然生成，危险命令仅作为引用证据；操作台完整展示攻击来源、传播路径、阻断点与最终业务结果。

### 1.4 应用前景

随着企业将 MCP 作为统一的工具接入总线，智能体将直接触达文件、网络、工单、代码仓库与堡垒机等敏感能力。溯界可部署为智能体平台与工具之间的**运行时安全网关**：为平台提供统一的授权边界、不可信内容传播约束、效果级拦截与全链路审计，尤其适用于安全运营（SOC）中“需要让智能体分析恶意样本与告警、但绝不允许其被样本反向操纵”的研判场景；也可作为通用智能体平台的安全合规组件，服务于大型企事业单位与国家级平台在自动化与智能化建设中面临的新型安全挑战。

### 1.5 威胁模型与安全目标

**保护目标**：

1. **机密性**：合成密钥、凭据、敏感文件与会话敏感数据不得流向未授权目的地；
2. **完整性**：外部内容、工具描述、工具返回、记忆与子 Agent 输出不得升级为授权或篡改可信任务边界；
3. **授权一致性**：执行动作必须属于用户身份权限、当前任务契约与有效能力租约的交集；
4. **可追溯性**：每个关键动作能够关联来源、转换、主体、工具、策略、审批、结果与影响对象；
5. **可用性**：防御不应通过“全部拒绝”获得安全指标，合法任务与危险证据分析任务都必须可完成。

**攻击者能力**：

| 攻击者 | 可控制内容 | 不应能够控制 |
|---|---|---|
| 恶意普通用户 | 用户消息、多轮拆分、角色伪装、编码混淆 | 系统策略、认证身份、控制面审批记录 |
| 外部内容攻击者 | 网页、文档、源码注释、工单、邮件、PDF 解析文本 | 任务契约、能力租约、执行凭据 |
| 恶意 MCP Server | 工具名/描述/Schema、返回字段、注册版本、受控靶场内实现 | 网关策略、其他 Server 凭据、宿主网络权限 |
| 记忆污染者 | 被写入并后续检索的记忆正文 | 记忆来源元数据、授权状态 |
| 被劫持子 Agent | 子任务输出、工具提议、传回文本 | 父任务以上权限、控制面确认 |

**可信计算基与信任边界**：可信的是认证与审批入口、策略及其签名版本、任务契约/租约服务、Host Adapter 与 MCP Proxy、来源存储、受信任效果适配器、受控执行器与网络出口代理；不可信的是所有模型输出、普通文本中的“管理员已批准”等声明、外部资源正文、MCP 工具描述与返回、记忆正文、子 Agent 输出，以及语义检测器给出的放行建议。对本作品**明确不保证**的边界，见 2.7 节。

## 第二章 作品设计与实现

### 2.1 系统方案总览

溯界位于**智能体宿主（Agent Host）**与 **MCP/本地工具**之间；在下列部署约束成立的前提下，它是受控工具调用的唯一通路。系统方案遵循三条总体原则：

- **数据面与控制面分离**：安全数据面在实时热路径上做授权与拦截；控制面（任务、策略、审批、告警、审计）不进入实时热路径，数据面仅在内存中使用已签名/带哈希的策略与合同快照，普通工具调用不同步查询数据库。
- **不可绕过的部署约束**：靶场中的智能体宿主不持有工具执行凭据，默认不能直接访问宿主文件系统、Docker Socket 与外部网络；所有敏感工具只能经网关/受控执行器；子 Agent 继承相同限制；模型 API、最终回复与日志预览同样视为数据出口；网关故障时高风险写操作 **Fail-closed**。
- **模型提议不等于授权**：所有模型输出、外部资源正文、MCP 工具描述与返回、记忆正文、子 Agent 输出以及语义检测器给出的放行建议，一律是不可信数据，不能签发或提升授权。

热路径如下：

```text
用户
  -> 智能体宿主 Agent Host
  -> Host Adapter / MCP Proxy
  -> 安全数据面（合同校验→内容入口→来源传播→动作映射→策略决策→审批/提交闸门）
  -> 受控执行器 / MCP Server
  -> 安全数据面（记录真实副作用）
  -> 智能体宿主
```

安全数据面由以下组件构成：任务契约束（Task Contract Cache）、工具注册守卫（Tool Registry Guard）、内容入口与规范化（Content Intake & Normalizer）、提示注入检测（Prompt Injection Detector）、来源引擎（Provenance Engine）、语义动作映射（Semantic Action Mapper）、策略决策点（Policy Decision Point）、审批/提交闸门（Approval/Commit Gate）、追踪发射器（Trace Emitter）。

### 2.2 实现原理

#### 2.2.1 可信任务契约与短期能力租约

**TaskContract（任务契约）**冻结一次任务的授权边界：可信目标、工作区根、允许用途、允许效果、禁止效果、预算、有效期与策略快照哈希。其生成规则强调：意图编译器只读取认证用户的原始任务、系统策略、角色权限与工具效果目录，**不读取随后获取的外部证据**；大模型可生成合同草案，但其权限上限由确定性的能力基线裁剪；外部内容、记忆或子 Agent 不能修改合同；扩权必须由真实用户在控制面确认并生成新版本，旧版本不可原地覆盖。

**TaskGrant（能力租约）**面向主体与子任务签发短期能力，子 Agent 权限满足严格不变量：

```text
Grant(子) ⊆ Grant(父) ∩ Need(子) ∩ Contract
```

#### 2.2.2 来源—用途信封

**ProvenanceEnvelope（来源—用途信封）**为每个内容构件记录来源、权威级别（authority）、完整性（integrity）、机密性（confidentiality）、允许/禁止用途、父来源、转换与来源区间映射。其传播不变量保证来源不可被“洗白”：

1. 普通模型转换不能提高 authority 或 integrity；
2. 派生物机密性取父输入最高等级，除非经过白名单可信脱敏器；
3. 确定性复制、切片、解码保留区间映射；摘要/自由改写仅保留父集合与保守依赖，**不伪造 token 因果**；
4. 对进入同一模型上下文的输入建立暴露集合（exposure set），自由文本输出保守继承该集合；
5. 允许用途默认取相关父输入用途的交集，结构化字段可基于字段级依赖单独计算；
6. 构件改名、重新编码、摘要与跨 Agent 传递均不清除来源。

由此，普通摘要、引用或子任务输出**不能获得执行授权**——这正是“不可信证据可分析、可利用、但不可授权”的机制基础。

#### 2.2.3 语义效果映射

工具名称不能直接作为策略语义。效果适配器（Effect Adapter）把**物化后的真实调用**转换为语义动作 SemanticAction：主体、工具身份与版本哈希、效果种类（如数据传输）、操作、资源、目的地信任级别、是否有副作用、是否可回滚、输入构件、参数哈希、合同与租约引用。这样策略针对的是“将要发生的效果”，而非工具的名字，避免同名工具绕过。

#### 2.2.4 策略 DSL 与三态决策

策略使用 YAML 描述、加载时转换为类型化 AST，**禁止 `eval` 与任意代码执行**；支持的操作符限定为 `eq/neq/in/not_in/matches/path_within/gte/lte/contains_any/exists`；事实命名空间覆盖 principal/contract/grant/action/data/provenance/tool/runtime/history；效果为 `allow/ask/block/hard_block`。涉及安全前提的缺失字段触发阻断，策略加载须完成 Schema 校验、类型检查、冲突检查与样例验证。系统内置五类策略：敏感目录写入与路径逃逸、敏感数据向非信任域外发、解码执行与危险 Shell 组合、代码检视任务中的 Git 推送、带秘密的子 Agent 派发。

对外决策只有三态 **ALLOW / ASK / BLOCK**，内部保留风险与命中事实，冲突规则为：

```text
HARD_BLOCK > BLOCK > ASK > ALLOW
```

其中 HARD_BLOCK 为系统硬策略，用户确认不能覆盖；语义模型只能**提高风险**（将 ALLOW 升级为 ASK/BLOCK、补充解释），不能覆盖硬拒绝、签发租约或将 BLOCK 降级为 ALLOW。

#### 2.2.5 动作判定顺序与内部状态机

每次工具调用按固定顺序判定：验证主体/会话/合同/租约/策略版本/工具身份 → 物化并规范化真实参数 → 生成语义动作 → 解析输入构件与暴露历史 → 检查身份权限与租约 → 检查合同的目标、资源与副作用范围 → 检查来源信封的 authority/confidentiality/allowed_uses → 执行硬策略与数据流策略 → 必要时运行**无工具**语义研判器 → 合并输出三态 → ASK 绑定实际参数与所有版本等待可信审批 → 执行前重新物化并做提交检查（Commit Check）→ 受控执行并记录真实副作用。

内部状态机覆盖 `PROPOSED→NORMALIZED→(BLOCKED | NEEDS_APPROVAL→APPROVED/REJECTED/EXPIRED | ALLOWED)→RESERVED→COMMIT_CHECK→EXECUTED/FAILED/RESULT_UNKNOWN/ROLLED_BACK`。审批在参数、目的地、资源、输入哈希、合同/租约/策略版本、工具描述/Schema/实现版本、数据敏感等级、父授权或预算/有效期发生变化时**自动失效**。

对本地副作用采用事务化处理：本地 `fs.write` 先在叠加层生成变更、检查 diff 后提交；本地 `git` 在临时工作树或本地裸仓库执行并检查 ref diff；受限 `exec` 在无特权、资源受限、默认无网络的容器中执行；对 `net.fetch`/远程写，调用前完成授权、调用后只记录结果，**不宣称通用回滚**。

#### 2.2.6 多源注入检测

检测结果是**风险证据而非授权**。检测流水线为：原文登记 → Unicode/不可见字符可视化视图 → NFKC/全半角规范化视图 → 有界编码解码视图 → 分块与跨轮组合视图 → 规则特征 → 轻量/大模型语义检测（按预算）→ span 级检测结论。**原文永不被规范化文本覆盖**，所有视图保存转换映射与版本。

覆盖三类来源：直接（用户越权、角色伪装、上下文劫持）、间接（网页/文档/源码/工单/邮件/Issue/工具描述/工具返回）、记忆（写入时扫描并保留来源，读取时重新扫描，正文永不携带授权）。检测器至少输出攻击来源、攻击族、命中区间、规范化视图、置信度、理由与检测器版本。

#### 2.2.7 意图—计划—工具对齐

系统**不读取也不声称还原私有思维链**，只使用可信用户目标与合同、智能体公开的结构化步骤、已执行事件、当前语义动作与来源/数据流事实，输出四类偏离：目标偏离（GOAL_DEVIATION）、资源偏离（RESOURCE_DEVIATION）、副作用偏离（SIDE_EFFECT_DEVIATION）、数据流偏离（DATA_FLOW_DEVIATION）。解释必须引用可验证事实，例如：“原始任务只允许读取工作区并写入本地报告；当前动作试图读取 `~/.ssh/id_rsa`，不在合同资源范围内，且目标为非信任域，因此命中资源偏离与秘密外发硬策略，决定阻断。”

#### 2.2.8 攻击后的安全恢复

阻断后，网关返回给智能体的不是原始秘密与攻击载荷，而是结构化的安全异常（SecurityException）：错误码、被阻断的效果、安全原因、允许的替代方案与决策 ID。智能体最多进行一次安全重规划；若再次提出等价越权动作则终止该分支，避免循环与确认疲劳。**安全完成的定义是“原始业务 Oracle 通过且无未授权副作用”**，而不是“是否被阻断”——这避免了用“全部拒绝”刷安全指标。

#### 2.2.9 MCP、子 Agent 与记忆防护

- **工具生命周期**：在工具信息暴露给模型之前完成 Server 身份登记、工具名/描述/Schema 扫描、同形/重名/功能重叠检查、描述与 Schema 哈希、信任等级与效果适配绑定；运行中任何注册变更生成新版本并使关联审批失效。
- **子 Agent**：为子任务创建子合同/子租约，权限取交集；只传递最小必要构件；敏感度与来源标签不因序列化丢失；子 Agent 输出视为不可信数据、不能携带新授权；父子事件通过 trace/parent ID 关联。
- **记忆**：记忆正文与授权记录物理/逻辑分离；写入保存来源、用途、敏感度与创建任务；检索时恢复信封并重新检测；“用户偏好/管理员批准”等记忆文本仅作为数据。

#### 2.2.10 溯源与证据

来源图区分**确定边**（读取自/派生自/暴露给/传递给/检索自/提议/授权自/执行/影响对象）与**推断边**（必须带置信度、单独标识、不与确定边混画）。token 来源口径遵循“可复现才声称”原则：对本地可复现的提示序列化与分词器保存字符区间到 token 区间的映射；对确定性复制/转换保留精确映射；对摘要/自由生成只声明父来源集合；对云模型隐藏包装只展示本地可验证范围，**不声称服务端完整 token 因果**。数据最小化方面：普通索引只保存脱敏摘要、哈希、类型与引用，完整参数/结果仅存于封闭靶场的加密证据区，演示一律使用合成秘密（honeytoken）。

### 2.3 软件流程

一次“分析含危险命令的告警附件并生成报告”的端到端流程为：

1. 用户在操作台创建任务，意图编译器生成 TaskContract 与首个 TaskGrant；
2. 智能体读取告警附件，内容入口登记原文、生成规范化视图并做注入检测；附件被标记为不可信数据；
3. 附件中的恶意指令试图诱导智能体读取凭据并外发；智能体据此提出工具调用；
4. 效果适配器把调用映射为语义动作；策略决策依次检查权限、合同、来源/用途与硬策略；
5. 命中“秘密外发”硬策略 → 决策 **HARD_BLOCK**；网关返回不含秘密的结构化安全异常与允许的替代方案；
6. 智能体在原授权边界内**一次安全重规划**（例如仅生成脱敏 IOC 与本地报告）；
7. 执行经提交检查后在受控执行器中发生，真实副作用（文件写入、无外发）被记录；
8. 操作台展示来源 DAG、传播路径、阻断点与最终业务结果；业务 Oracle 判定报告正确且无未授权副作用，任务安全完成。

### 3.7 证据保存与可复算性

### 3.8 测试局限与未验收项

1. 完整“三来源 × 七绕过”矩阵未验收；正式独立任务登记与五配置主比较（C/A/Q/R）未形成；
2. 真实模型规模小（M21 云合计 18 请求、M19 云 31 请求），仅用于工程可行性验证；
3. **macOS 上 Git 相关用例失败**：来源检查 `path_identity()` 按设计拒绝含符号链接的路径，而 macOS 的 `/var → /private/var` 使系统临时目录触发 `GIT_ALIAS_FORBIDDEN`；**这是测试夹具可移植性限制，不是授权/绕过缺陷**，Linux/Windows CI 不受影响；
4. 新版 Linux 整体隔离与性能未验收；外部基准仅为受限子集；
5. 自适应攻击（在预算内观察并重写载荷）未实现。

## 第四章 创新性说明

本作品不主张单项机制的首创（见 1.2 节），创新性体现在面向“安全研判”场景的**机制组合与工程闭环**。以下三点均可由第三章的真实副作用 Oracle 对照验证，而非依赖模型自评。

### 4.1 来源—用途约束：让不可信证据可分析、但不可授权

传统内容防护多依赖“检测—拒绝”范式：一旦判定内容为恶意，便整段阻断，导致安全研判这类**必须阅读攻击内容**的任务无法完成。本作品的差异在于把“内容是否可信”与“内容能否授权”分离：不可信内容被允许读取、分析与引用，但其来源—用途信封不允许 authority/integrity 提升，也不允许其经摘要、记忆、子 Agent 或工具返回升级为执行授权。

**可验证差异**：同一攻击载荷下，“仅分类器拒绝”会同时损失业务结果；本作品则阻断越权副作用而保留业务结果。这一差异由“安全研判保全率”与“正常任务完成率”两项指标同时刻画，不能用单一“阻断率”替代。

### 4.2 攻击后的安全任务持续执行：把“被阻断”与“安全完成”区分开

多数网关在阻断后终结任务或直接报错。本作品在阻断后返回**不含秘密的结构化安全异常**与允许的替代方案，引导智能体在原授权边界内进行一次安全重规划，使原始研判目标仍可达成。

**可验证差异**：本作品把“安全完成”定义为“原始业务 Oracle 通过且无未授权副作用”，从而在机制上排除“通过全部拒绝刷高安全指标”的捷径；同时以“平均每正常任务 ASK 数”等指标约束确认疲劳。

### 4.3 效果级工程闭环：以真实副作用而非模型自评判分

本作品对真实工具参数、来源依赖、任务授权与执行状态做统一判断，并以文件系统、封闭网络接收端、真实子进程、本地 Git refs 与记忆数据库的**真实状态**作为安全 Oracle；语义模型只能提高风险等级，不能覆盖硬拒绝或扩权。

**可验证差异**：安全结论由独立于被测智能体的外部副作用判定，可反复重算；这使“模型自己没有提出危险动作”与“网关确实拦截了危险动作”在证据上可区分，避免了以模型自评冒充防护效果。

### 4.4 组合与工程落地

上述三点由统一的六大核心对象（TaskContract、TaskGrant、ProvenanceEnvelope、SemanticAction、DecisionRecord、TraceEvent）与快慢路径分层（内存校验→确定性检查→本地规则→按需语义研判→人工确认）支撑，在真实 MCP 工具链上形成端到端闭环，并保证语义模型不成为每次调用的必经环节，从而兼顾安全与可用性。

## 第五章 总结

### 5.1 工作总结

本作品面向大模型智能体的提示注入与工具滥用，设计并实现了一套部署在智能体宿主与 MCP/本地工具之间的运行时安全网关“溯界”。系统以可信任务契约冻结授权边界、以来源—用途信封约束不可信内容的传播与使用、以效果级执行闸门实施 ALLOW/ASK/BLOCK 三态处置，并在攻击被阻断后通过结构化安全异常引导智能体继续完成任务；同时以真实副作用作为安全 Oracle，覆盖文件、网络、进程、Git、记忆与子 Agent 等工具面。

围绕赛题的五项能力，本作品在直接/间接/记忆三类注入来源、意图—计划—工具对齐、语义化策略与三态、跨 MCP 与多层 Agent 溯源防护、以及多语言与多种绕过手法上均已建立实现与对应证据；具体实验数据、分母与适用边界见第三章。

### 5.2 与设计目标的差距与残余风险

为如实反映现状，此处列出尚未闭环的事项（详见第三章与项目交接资料）：

- **完整的“三来源 × 七绕过”覆盖矩阵**与更大规模的独立任务登记尚未完成；
- **基线与消融的主比较**（不安全的智能体、强静态网关、完整系统与两项消融）尚未形成冻结测试集上的对照成绩；现有结果多为确定性回归与**小规模**真实模型实验，**不能**表述为比赛攻击成功率或公开基准成绩；
- **新版整体隔离与性能**尚未在 Linux 环境完成验收；历史容器拓扑不能替代当前拓扑；
- 控制面以 Python 实现，原设计中的 Java/MySQL 控制面未落地；子 Agent 目前运行于同一宿主进程内，尚未做操作系统级隔离；
- 本地 token 映射不等于云模型内部 token 因果；引用字面核验不证明语义正确。

### 5.3 展望

后续工作将沿两条主线推进：一是把机制验证推进到**冻结测试集上的独立任务登记与多基线消融**，并把“三来源 × 七绕过”整理为可复算的覆盖矩阵；二是把隔离与性能验证前移到**干净的 Linux 环境**，补齐操作系统级隔离与跨平台部署验收，使安全声明与工程证据在多环境下均可复现。
